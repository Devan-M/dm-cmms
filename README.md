# DM-CMMS

![Status](https://img.shields.io/badge/status-em%20desenvolvimento-yellow)
![Licença](https://img.shields.io/badge/licença-a%20definir-lightgrey)
Sistema de **Computerized Maintenance Management System (CMMS)** para centralizar o planejamento, o acompanhamento e o histórico das atividades de manutenção.

## Visão geral

O DM-CMMS foi concebido para apoiar equipes de manutenção na organização de ativos, ordens de serviço e rotinas operacionais, oferecendo uma visão mais clara das tarefas e do histórico dos equipamentos.

## Principais recursos

- Cadastro e acompanhamento de ativos;
- Registro e gestão de ordens de serviço;
- Controle de manutenções preventivas e corretivas;
- Histórico de intervenções e ocorrências;
- Acompanhamento de status, prioridades e responsáveis;
- Organização das informações em um único lugar.

> Os recursos disponíveis podem variar conforme a versão atual do projeto.

## Pré-requisitos

Consulte os arquivos de configuração e documentação do projeto para identificar os requisitos exatos de execução. Em geral, é necessário ter:

- Git;
- O runtime e o gerenciador de pacotes definidos pelo projeto;
- Banco de dados e demais serviços configurados, quando aplicável.

## Instalação e execução

Clone o repositório e entre na pasta do projeto:

```bash
git clone https://github.com/Devan/dm-cmms.git
cd dm-cmms
```

Em seguida, instale as dependências usando o gerenciador indicado pelos arquivos do projeto e execute o comando de desenvolvimento correspondente.

Antes de iniciar, configure as variáveis de ambiente necessárias em um arquivo `.env`, quando aplicável. Nunca versionar credenciais ou informações sensíveis.

## Estrutura do projeto

A estrutura pode ser consultada diretamente no repositório. Recomenda-se manter a separação entre código da aplicação, configurações, testes e documentação para facilitar a manutenção.

## Contribuição

1. Crie uma branch para sua alteração:

	```bash
	git checkout -b feature/minha-alteracao
	```

2. Faça as alterações e valide o projeto localmente.
3. Registre um commit objetivo.
4. Abra um pull request descrevendo o que foi alterado e como validar a mudança.

## Boas práticas

- Não inclua segredos, tokens ou dados reais no repositório;
- Mantenha nomes e mensagens de commit claros;
- Atualize a documentação quando alterar o comportamento da aplicação;
- Adicione ou ajuste testes sempre que aplicável.
